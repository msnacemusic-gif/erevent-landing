# Работа над сайтом «СОБЫТИЯ РУМ»

## Как общаться с заказчиком

**Все правки заказчик делает через Claude, а не сам.** Не объяснять, какой
файл открыть, какую строку поменять и куда положить картинку. Не предлагать
«скопируйте строку и поменяйте значения». Заказчик присылает данные — тексты,
фото, списки — и правку вносит Claude.

Исключение — только то, до чего у Claude физически нет доступа: кабинет
Cloudflare, Brevo, @BotFather, домен. Там шаги описывать нужно, потому что
иначе не сделать.

Заказчик пишет по-русски и ждёт ответов по-русски. Технические термины
разворачивать простыми словами.

## Что важно про содержание

Все тексты, цифры, кейсы и отзывы — реальные данные компании. Ничего не
выдумывать: если данных не хватает, спрашивать. Заглушки должны выглядеть
заглушками, а не правдоподобным текстом.

## Как устроен сайт

Статические файлы в корне репозитория, без сборщиков и зависимостей.
GitHub Pages отдаёт ветку `main`, правки выкатываются автоматически.

- `index.html`, `styles.css`, `script.js` — главная и общий код
- `art-obekty/`, `mebel-oborudovanie/`, `keitering/`, `ekrany-svet-zvuk/` —
  страницы направлений, общие `page.css` и данные в блоке `page-data`
- `privacy/` — политика конфиденциальности
- `media/` — фото, логотипы, hero-видео, иконки
- `form/` — приёмник заявок на PHP: `submit.php`, общий `lib.php`,
  досылка уведомлений `retry.php`, вложения в `uploads/`. Настройки
  `form/config.php` в репозитории не лежат: их собирает выкладка из секретов
  GitHub. Диагностика связи — `form/diag.php` под паролем страницы заявок
- `zayavki-pzned3/` — страница просмотра заявок, вход по паролю
- `serverless/telegram-relay.js` — прежний приёмник на Cloudflare, больше
  не используется, оставлен на случай отката
- `project/`, `chats/` — исходные макеты Claude Design, сайт их не использует

Сайт выкладывается на хостинг Timeweb по FTP из `.github/workflows/deploy.yml`.
Путь на сервере отсчитывается от домашней папки аккаунта: `/sobroom/public_html/`.
Заявки пишутся в базу MySQL на том же сервере и только после этого уходят
в Telegram и на почту — так первичная запись остаётся в России.

Сервер хостинга не выпускает исходящие соединения, поэтому уведомления с него
не доходят. Схема такая: браузер отправляет заявку в `form/submit.php`, ждёт
успешного ответа и только тогда дублирует те же данные в приёмник
на Cloudflare — он пишет в Telegram. Файл повторно не отправляется, вместо
него идёт ссылка на сохранённое вложение. Дошедшее уведомление браузер
отмечает через `form/notified.php` (отметка принимается только с подписью),
чтобы очередь не отправила дубль. Что не дошло — остаётся в очереди, её
разбирает `form/retry.php` по расписанию; на странице заявок такие помечены
«ждёт».

Порядок нарушать нельзя: если `form/submit.php` не ответил успехом, второй
запрос не отправляется — иначе уведомление ушло бы по заявке, которой нет
в базе.

`styles.css` и `script.js` общие для всех страниц. Скрипт проверяет наличие
блока перед обращением к нему — страница без кейсов или без видео его не
роняет.

## Дизайн-система

Менять без запроса нельзя. Токены в начале `styles.css`.

- Акцент — лаймовый `#9fe870`, только кнопки и активные состояния
- Холст `#e8ebe6`, карточки белые, тёмные секции `#0e0f0c`
- Manrope 800/900 для заголовков, Inter для текста
- Радиус 24px, пилюли 9999px, теней нет
- Анимации сдержанные, все уважают `prefers-reduced-motion`

## Проверка перед выкаткой

Локально: `python3 -m http.server 8000` в корне.

Проверять в браузере на ширинах 320–1920: переполнения по горизонтали,
ошибки в консоли, работу форм и интерактива. Headless Chromium не умеет
H.264 — hero-видео подхватывает запасной WebM, это нормально.
