# Техническое задание: одностраничный лендинг «СОБЫТИЯ РУМ»

**Формат:** промт-бриф для Claude Design
**Тип продукта:** одностраничный лендинг (single page, навигация — якорные ссылки)
**Язык интерфейса:** русский
**Заменяет:** существующий сайт erevent.ru (Creatium)

---

## 0. Главное правило по дизайну

**Все визуальные параметры берутся ИСКЛЮЧИТЕЛЬНО из загруженной в проект дизайн-системы.**

Из дизайн-системы используются: цветовая палитра (включая тёмную/светлую тему, если она там определена), типографика и шрифтовые пары, логотип и его версии, стили кнопок, полей форм, карточек, теней, скруглений, сетки, отступов, иконок.

**Запрещено:** придумывать новые цвета, подключать сторонние шрифты, менять начертания логотипа, использовать градиенты/эффекты, которых нет в дизайн-системе. Если для какого-то элемента в дизайн-системе нет готового токена — собрать элемент из существующих токенов, а не вводить новый.

## 1. О компании и цели сайта

**Компания:** «СОБЫТИЯ РУМ» — техническое оснащение мероприятий, застройка стендов и декораций, организация мероприятий полного цикла в Москве и по России.

**Позиционирование (ключевое сообщение):** мы работали на стороне организаторов, поэтому говорим с заказчиком на одном языке и предлагаем не «закрыть блок», а экономически выгодное решение задачи.

**Целевая аудитория:** event-агентства, генеральные подрядчики, ивент-менеджеры и маркетологи корпораций, продюсеры фестивалей и форумов. B2B, люди в дефиците времени, принимающие решение по скорости расчёта сметы и по портфолио.

**Главная цель лендинга:** получить заявку на расчёт сметы.
**Целевые действия по приоритету:**
1. Отправка формы «Рассчитать смету».
2. Переход в Telegram / WhatsApp.
3. Звонок по телефону.

**Ключевой оффер, который должен читаться за 5 секунд:** смета в день обращения, обычно за 3 часа.

## 2. Референсы и что именно из них берём

### 2.1 launchuicomponents.com — структура, компоновка блоков, motion

Берём:
- модульную блочную структуру и ритм страницы: hero → лента логотипов → bento-сетка возможностей → фичи → соцдоказательство → FAQ → CTA → футер;
- **bento grid** — сетка карточек разного размера в одном блоке, с «живым» содержимым внутри карточек, а не просто текст;
- бесконечные **марки-ленты** (логотипы клиентов, теги услуг) с плавным бесшовным скроллом и градиентным затуханием по краям;
- аккуратные микроанимации: появление элементов по скроллу с задержкой (stagger), лёгкое движение при наведении, анимированные счётчики;
- прилипающий полупрозрачный navbar с эффектом «стекла» при скролле;
- аккордеон FAQ и финальный CTA-блок во всю ширину.

**Не берём:** цвета, шрифты, иллюстрации, тематику SaaS/dev, блоки с ценами и тарифами.

### 2.2 lumarise.ru — тон, hero, подача проектов

Берём:
- **hero с фоновым showreel-видео** и крупной сдержанной типографикой поверх;
- минимализм: много воздуха, короткие строки, служебные подписи в квадратных скобках как разделители смысловых зон (`[направления]`, `[кейсы]`, `[этапы работы]`) — оформить типографикой из дизайн-системы;
- **нумерованный список проектов** (01, 02, 03…) с раскрытием изображения при наведении вместо плотной сетки карточек;
- отдельный блок **этапов реализации проекта** с горизонтальной/вертикальной прогрессией;
- лаконичный футер: контакты, мессенджеры, ничего лишнего.

**Не берём:** цветовую схему, шрифты, английские заголовки, структуру с отдельными страницами проектов.

## 4. Требования к анимации и motion-графике

**Общий принцип:** анимация подчёркивает структуру, а не развлекает. Ничего не должно мешать быстро дойти до формы.

- **Появление по скроллу:** fade + сдвиг вверх на 16–24 px, длительность 400–600 мс, easing типа `cubic-bezier(0.16, 1, 0.3, 1)`, задержка между соседними элементами 60–100 мс. Анимация срабатывает один раз, при появлении ~20% блока во вьюпорте.
- **Hover:** подъём карточки на 2–4 px, изменение границы/тени, масштаб фонового изображения до 1.03. Длительность 200–250 мс.
- **Марки-ленты:** бесшовный цикл 25–40 с, линейное движение, пауза при наведении, маска-затухание по краям.
- **Счётчики:** отсчёт от 0 за 1.5–2 с с замедлением в конце.
- **Hero-видео:** параллакс со смещением медленнее скролла, плавное затемнение при уходе блока вверх.
- **Timeline этапов:** прогресс-линия заполняется по мере скролла, активный этап подсвечивается.
- **Аккордеон и меню:** плавное раскрытие по высоте, поворот иконки.
- **Обязательно:** поддержка `prefers-reduced-motion` — при включённой настройке все перемещения и автоплей отключаются, остаётся мгновенное появление контента.
- **Запрещено:** анимации дольше 800 мс, эффекты пружины/подпрыгивания, параллакс текста, вращения, анимации, блокирующие скролл (scroll-jacking), появление элементов при каждом проходе скролла.

## 6. Технические требования

- **Производительность:** Lighthouse Performance ≥ 85 на мобильных, LCP < 2.5 с. Изображения в WebP/AVIF с ленивой загрузкой и корректными `width`/`height`. Showreel — не тяжелее 8 МБ, кодек H.264/WebM, `preload="none"` на мобильных.
- **Доступность:** контраст текста не ниже AA, фокус-состояния для всех интерактивных элементов, alt-тексты, навигация с клавиатуры, семантические заголовки h1→h3.
- **SEO:** один h1; title и description для страницы; Open Graph и favicon из дизайн-системы; микроразметка Schema.org — `Organization` (или `LocalBusiness`) и `FAQPage`; sitemap.xml и robots.txt; ЧПУ-якоря.
- **Редиректы 301** со старых адресов на соответствующие якоря новой страницы:
  - `/zastroika` → `#services`
  - `/tv-led`, `/arenda-zvuka` → `#services`
  - `/arenda-shatrov` → `#services`
  - `/arenda-mebeli-1` → `#services`
  - `/arenda-fotozon` → `#services`
  - `/#cases` → `#cases`, `/#cantacts` → `#contacts`
- **Приём заявок:** заявка одновременно уходит в Telegram-бот, на почту info@erevent.ru и в таблицу (Google Sheets / аналог). CRM не используется. Защита от спама — honeypot + ограничение частоты отправки, без видимой капчи.
- **Аналитика:** Яндекс.Метрика с вебвизором; цели — отправка формы, клик по телефону, клик по Telegram, клик по WhatsApp, скролл до кейсов.
- **Правовое:** баннер согласия на обработку данных (152-ФЗ), страница/модальное окно политики конфиденциальности.

## 7. Чего делать не нужно

- Не создавать отдельные страницы услуг — весь контент на одной странице.
- Не публиковать цены и прайс-листы: аренда оформляется по запросу.
- Не делать отдельный блок про работу с юрлицами и документооборот — эта информация даётся клиентам по запросу.
- Не добавлять блоки отзывов клиентов, пока нет реальных текстов.
- Не использовать стоковые фотографии мероприятий — только реальные фото проектов; до их загрузки использовать нейтральные плейсхолдеры.
- Не подключать сторонние UI-киты и шрифты помимо дизайн-системы.
- Не добавлять чат-виджеты, всплывающие окна с таймерами и запросы на уведомления.

## 8. Критерии приёмки

1. Все цвета, шрифты и элементы визуально соответствуют загруженной дизайн-системе, без посторонних значений.
2. Все 12 блоков реализованы в указанном порядке, тексты из ТЗ перенесены без искажений.
3. Форма отправляется, данные приходят во все три канала, экран успеха отображается.
4. Все CTA-кнопки ведут к форме, кнопки мессенджеров открывают корректные ссылки.
5. Анимации работают на десктопе и мобильных, отключаются при `prefers-reduced-motion`, скролл нигде не «залипает».
6. Страница корректно отображается на 360, 768, 1024 и 1440 px.
7. Lighthouse: Performance ≥ 85, Accessibility ≥ 90 на мобильных.
8. Проверены 301-редиректы со всех старых адресов.
